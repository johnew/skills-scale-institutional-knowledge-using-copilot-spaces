# OctoAcme Project Management Docs

This directory contains OctoAcme's project management guidance, from project initiation through delivery and continuous improvement.

## Project management process summary

OctoAcme follows an iterative lifecycle: teams validate the need, outcomes, stakeholders, and resources during initiation, then plan prioritized work, acceptance criteria, estimates, milestones, dependencies, and a Definition of Done. During execution, teams track progress on a project board, deliver small reviewed increments, and manage risks with clear owners, mitigations, regular reviews, and escalation paths.

The Project Manager coordinates delivery, risks, and communication; the Product Manager owns outcomes and priorities; developers build and test; QA validates quality and acceptance criteria; and stakeholders provide input and approvals. Standups surface progress and blockers, weekly syncs review delivery and risks, and demos and stakeholder updates maintain alignment.

Quality practices include unit and applicable integration tests, end-to-end smoke tests for critical flows, security scanning, manual QA when needed, and CI checks for tests and linting before review. Releases require acceptance criteria, passing CI and security scans, release notes, smoke tests, and a rollback plan, followed by post-deployment verification. Retrospectives after sprints, releases, or milestones turn learnings into a small set of tracked improvement actions.
